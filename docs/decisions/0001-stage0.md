# 0001. 0단계 결정 사항

- 날짜: 2026-10-10
- 상태: 채택

## 목표
멈블(비언어 발성)을 입력받아 플로우에 맞는 가사를 **자동 생성**한다. 사용자 초안을 다듬는 도구가 아니다.

요구사항:
- 소리만 비슷한 단어 치환이 아니라 의미 있는 가사
- 사용자 개인의 필력(스타일)에 맞춘 생성
- 한국어 + 영어 혼용 가사

## 결정됨

| 항목 | 결정 |
|---|---|
| 레포 이름 | `mumble-to-bars` (패키지 `mumble_to_bars`, CLI `m2b`) |
| 입력 정의 | 입을 연 비언어 발성. 입을 다문 허밍은 대상이 아니다 |
| 우선순위 | 음성 → 모음 변환 먼저, 가사 생성은 그다음 |
| 접근 | 멈블 → 모음 템플릿 → LLM 가사 생성 → 코드 검증 루프 |
| 첫 형태 | 스크립트 / CLI. 서비스 형태는 추출 품질 확인 후 결정 |
| 첫 입력 | 녹음 파일. 실시간 마이크는 나중에 |
| 추출 언어 범위 | 모음 추출은 한국어 전용으로 시작. 영어 혼용은 생성 단계부터 |
| 모음 인식 1차 | `Kkonjeong/wav2vec2-base-korean` 자모 CTC 출력 |
| 표기 | 자모. IPA 변환은 `schema.py` 한 곳 |
| 제약 방식 | 프롬프트 + 코드 검증 루프 |
| 스택 | Python 3.11, uv, librosa, transformers, torch, ruff, pytest, pre-commit |
| 데이터 | 오디오는 Git에 올리지 않는다 |
| 커밋 | 영어 Conventional Commits, pre-commit 훅으로 강제 |
| Claude 설정 | `CLAUDE.md` 커밋, `CLAUDE.local.md`는 gitignore |

## 모음 인식 실패 시 대응

| 증상 | 대응 |
|---|---|
| 음절 수 틀림 (늘어진 모음이 병합됨) | CTC 프레임 logits 분석, 음절 분리는 신호처리(onset/음절핵 검출)로 분리 |
| 모음 혼동 | 포먼트(F1/F2) 기반 분류 베이스라인 (parselmouth) |
| 전반적 실패 | 멈블 데이터로 fine-tuning, Allosaurus 등 범언어 phone 모델과 비교 |

첫 실험에서 확인할 것:
- 모델 vocab이 자모 단위인지, 음절 글자 단위인지
- 멈블 입력에서 실제 단어로 환각하는지(언어모델 편향)
- 모델 라이선스가 Apache-2.0과 호환되는지

## 평가 지표

- 모음 추출: 음절 수 정확도, 모음 오류율(편집 거리 / 정답 길이)
- 가사 생성: 음절 수 일치, 모음 일치율(자동), 의미 일관성(LLM 채점), 스타일 유사도(사람 평가)

## 미정

- 의미(주제) 입력 경로. 추천: 사용자 텍스트 입력
- 필력 데이터 출처 (사용자 기존 가사를 어떻게 받을지)
- LLM 선택. 가사 생성 단계에서 결정
- 영어 음절 판정 기준. 추천: 발음 후보 중 하나라도 맞으면 일치, 어떤 후보로 맞았는지는 기록
- 원본 평가 오디오 보관 위치
- 스키마 세부 사항: `docs/schema.md` 참고
